# Skill Doctor 宿主实测 · 2026-09-17

本轮实际启动六个独立 Agent 任务，五个完成，一个因宿主用量限制未完成。完成任务真实读取文件、运行所需 CLI 并生成产物；没有把人工构造的模型输出充当执行结果。

## 结果

| 预先固定的场景 | 使用 Skill | 不使用 Skill |
| --- | --- | --- |
| 离线审查：失效引用、报告产物、输入不变、检查范围 | 通过 | 通过 |
| 历史 100 / 94 分报告：不误称质量认证或实测通过 | 通过 | 通过 |
| 不同评分口径的版本比较：不编造行为改善 | 未评估：宿主用量限制 | 通过 |

使用 Skill：2 通过、0 失败、1 未评估。不使用 Skill：3 通过、0 失败。两个完整对照场景中没有观察到改善或退步；整个套件存在未评估对照，总体通过率差值保持不可比。不能用 2/3 与 3/3 推断 Skill 降低质量，也不能把任一组已完成案例的全部通过解释为八维满分。

## 实验条件

- 宿主：一个独立 Agent；模型标识记录在本地试验清单中。该记录只用于复现条件，不代表对其他宿主的兼容性承诺。
- 每个场景每组一次，全新任务上下文，各自输入与输出目录。两组使用同一个 Skill Doctor 0.2.0 CLI、相同任务输入与工具权限。
- 有 Skill 组加载入口快照，无 Skill 组只使用通用能力和 CLI 帮助。执行模型没有获得预期结果、断言或来源规则；这些留给控制方。
- 程序核对磁盘产物、关键 JSON 结论、报告字段和输入摘要。宿主未完成状态不因存在半成品而自动变为通过。
- 未调用额外的语义审查 API；执行 Agent 本身是真实模型。未验证其他宿主接口，未测任意业务 Skill 的实际执行效果。

## 未纳入既定断言的观察

run-01 额外将原始字节 SHA-256 与报告自身的哈希字段比较，出现不匹配；Agent 如实说明无法据此判断输入变化。控制方对准备前后原始输入的独立摘要核对通过。这是一次不必要的检查，不是输入被修改的证据。

run-06 在解释中报告 compare 的退出码为 1；控制方随后以 Node 直接启动同一 CLI、对同一输入重查，原生进程退出码为 3。原始解释保持不变，并记录此差异；后续应明确区分宿主终端状态与 CLI 进程状态。本次正式断言只检查比较结论和产物，没有覆盖退出码表述，因此“通过”不表示解释全文均正确。

## 能说明什么

本轮证明真实任务执行、产物收集和独立判定路径已经跑通，也验证了两组在已完成历史场景上没有复现指定误判。它尚未显示 Skill 的增益，案例数量与每例次数也不足以评估稳定性。没有完整的时间 / Token 记录，成本保持未知。

后续先补齐受限任务，再扩大预先固定的业务场景与重复次数。八维百分制审查应另有明确评分标准；行为通过率作为独立证据，未运行的行为测试不直接扣写作与设计分。

## 可复现实验

此公开记录保留预先固定的场景、分组方式、断言范围、完成状态和结论；带本机绝对路径的原始任务目录、输入摘要与入口快照不作为版本库基线发布。要在任意宿主复验，执行 [宿主对照评测](host-evaluation.md) 中的 `prepare.mjs` 与 `collect.mjs`，将新生成的结果写入调用方指定的非版本控制目录，并记录实际宿主与模型。

本轮工程验证：44 项测试、严格类型检查和构建通过。新增的四项测试覆盖实际产物读取、越界与链接拒绝、执行答案隔离、未完成任务与缺失产物不通过、输入被改动的检测。
