# 宿主 Agent 对照评测

参考 [Anthropic skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md) 的同题执行、基线、独立评分流程。复用本项目 RegressionCase / Grader / Benchmark 协议；不把一份 SKILL.md 当成通用执行器。

当前支持的具体流程是：控制方准备任务包，宿主独立 Agent 完成实际任务，代码从磁盘采集产物并导入 Grader。它不依赖额外的 Chat Completions endpoint，但需要宿主本身能运行 Agent 和文件工具。每个新宿主都需要提供等价任务执行、产物采集和隔离过程，并以其自身试验记录验证。

## 固定输入，再执行

在项目根目录完成构建后，准备一个新目录；最后一个参数记录实际宿主模型，不负责切换模型：

```sh
node evaluations/skill-doctor/prepare.mjs .skill-doctor/pilot-001 <实际模型标识>
```

生成三个场景各有 / 无 Skill 两个任务，共六次独立执行。每组使用同一个 CLI、相同输入、相同模型和工具权限。现有场景是离线审查、旧高分解读、跨评分口径比较，来源是历史故障，不是全面能力量表。fixtures 中两份报告是本项目 0.1.0 / 0.2.0 的真实静态审查快照，不是模型执行记录。

控制方保留根目录的 cases.json（答案与断言）和 manifest.json（分组、输入摘要、模型、工具位置）。每个执行 Agent 只获得自己目录内的 task.json 的 input / context、inputs、可写 outputs，以及有 Skill 组的 skill/SKILL.md。不要把整个案例对象传给执行 Agent。

每次创建全新任务上下文，不沿用上一案例的对话。有 Skill 组加载快照；无 Skill 组使用通用能力并不加载任何 Skill。共同允许 Node 和 manifest 中 CLI 的 --help；明确相对路径基于各自任务目录，输出路径覆盖入口的机器默认目录。禁止执行方读套件答案、源码测试、其他运行目录，或修改输入。记录每次宿主任务标识、模型和执行日志。

这是任务上下文与目录隔离，不是操作系统强隔离；共享宿主的工具权限和技能目录可能产生污染。用于更高保证的实验时，应由真实运行器提供文件白名单、隔离工作区和网络策略。审查本身也只能使用被授权的文件和服务。

## 采集与评分

执行方按任务要求写 summary.json 以及所需审查 / 比较报告。控制方依据宿主完成事件将 manifest 中对应 run 的 status 改为 completed，并记录 agentTask；宿主额度耗尽等未完成执行保留非完成状态和原因，不凭半成品评分。控制方收集实际文件，不接受“已生成产物”的文字声明替代文件。采集拒绝越界、符号链接和过大文件，并比对输入文件摘要。

```sh
node evaluations/skill-doctor/collect.mjs .skill-doctor/pilot-001
```

输出 captured-outputs.json、benchmark.json 和 benchmark.md。原始任务输出保持在各 run 目录，不被规范化结果覆盖。未提交输出的案例保持未评估；错误内容或缺失必需产物不通过。本轮使用确定性断言验证关键声明、报告字段、实际产物和输入不变；没有把解释文字的全面质量当成已自动评分。

`mode: import` 表示结果由宿主执行后导入，并不表示它是模拟数据。是否真实执行由任务日志和产物记录说明；手写或伪造的导入文件无法仅凭 Schema 验证变成可信执行证据。

## 解读

- 通过率只对应固定案例中的断言，不是八维质量分或任意任务成功概率。
- 有 / 无 Skill 都通过，说明当前案例未显示增益；不能归功于 Skill，也不能由此证明 Skill 在所有任务上无用。
- 当前试验每例每组仅一次，没有稳定性、显著性或成本优势结论。时间和 Token 未完整采集时保持未知。
- 模型、工具、案例或评分标准改变后重新建立基线。扩展案例应先固定预期，保留失败结果，不为获得有利差值反复挑选案例。
- 未来百分制审查分与这些行为结果分开呈现；未运行行为评测不应直接扣写作与设计分。
