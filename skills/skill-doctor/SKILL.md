# Skill Doctor · 技能体检

对含 `SKILL.md` 的技能目录做证据化审查：问题清单（文件行号与原文）、八维设计评分、补丁债和版本对比。用户可选择快速静态审查或完整八维审查。审查保持输入技能不变；用户要求优化时，依据发现提出改法并在已授权范围内修改。

## 运行方式

优先使用 PATH 中已安装的 `skill-doctor`（要求 Node >= 22.18）。如果命令不可用，先定位实际的项目根目录（含 `package.json` 和 `dist/cli.js`）；若当前环境只有发布包，读取[运行时准备](references/runtime-setup.md)安装或定位该项目。随后运行 `node <项目根目录>/dist/cli.js`；不得猜测固定安装目录或报告目录。每次报告都使用调用方明确指定的新输出路径。

以下命令以已安装 CLI 为例；源码检出环境将 `skill-doctor` 替换为实际项目中的 `node dist/cli.js`。示例中的技能目录和报告路径需按当前工作目录调整。

## 选择审查范围

用户已经明确范围时直接执行，不再询问：

- “快速、静态、离线、只看结构”使用快速静态审查。
- “完整、八维、语义”使用完整八维审查。

用户只说“检测、体检、审查”等、范围不明确时，先发送以下提示并等待用户选择。选择前不生成或展示评分报告：

> 请选择审查范围：
> 1. **快速静态审查**：离线且速度快；检查结构、长度、重复、引用、目录和规则信号，给出静态暂评分。职责边界与异常处理不评分。
> 2. **完整八维审查**：在静态检查外进行语义审查，耗时较长；八个维度均给出百分制评分、理由和逐字证据。
>
> 可回复“快速静态”或“完整八维”。

快速静态审查使用 `audit --static`。交付时说明 `semantic.status=not_requested`，将分数称为“静态暂评分”；职责边界和异常处理保持待语义审查，不称为完整质量结论。

完整八维审查先进行静态预扫描，但这是内部中间步骤。可以告知“静态预扫描完成，正在语义审查”，不要单独向用户交付静态评分。读取并执行[完整八维流程](references/complete-review.md)；只有流程中的完成门禁通过，才能交付八维评分。

## 30 秒快速体检（用户明确选择）

用户说“快速静态审查”时，立即运行：

```sh
skill-doctor audit ./target-skill --static --format html --out ./skill-review.html --fail-on none
```

交付时只说明结构、引用、长度、重复和规则信号的静态暂评分；职责边界与异常处理待完整八维审查。报告生成后即可打开 HTML 查看证据。

## 快速静态审查（用户明确选择）

`--out` 拒绝覆盖已有文件，每次用新的文件名。

```sh
# Markdown 报告
skill-doctor audit ./target-skill --static --format md --out ./skill-review.md --fail-on none

# HTML 报告：可筛选问题、展开源码证据和补丁建议，双击即可看，无需起服务
skill-doctor audit ./target-skill --static --format html --out ./skill-review.html --fail-on none

# JSON（供后续 compare 用）
skill-doctor audit ./target-skill --static --out ./skill-review.json --fail-on none
```

体检对象可以是任意含 `SKILL.md` 的目录。输出路径应在调用方可写的工作区或用户指定位置，不复用已有基线报告。

## 改版前后对比

```sh
skill-doctor compare ./before.json ./after.json --format md
skill-doctor diff ./old-skill ./new-skill  # 只看差异，不自动应用
```

先读取比较条件与不可比原因，再解释新增、消失的问题；行为改善以固定案例的实际回归结果为依据。

## 批量体检技能库

当用户提供技能库根目录时，用当前宿主可用的文件枚举工具查找直接包含 `SKILL.md` 的子目录，逐个运行静态预扫描。完整体检继续对每个目标执行上面的宿主语义审查与导入，不将静态批次当成完整审查。没有用户指定根目录时，不猜测任何默认技能安装位置。

读取各报告，按严重度与问题类型归并，附证据位置、检查范围和报告路径；检查范围不同的技能分别说明。

## 检查范围与解读

- 对话入口在范围不明确时先让用户选择。CLI 的 `audit` 不指定模式时生成静态报告但退出 3，表示完整审查未完成；快速静态审查使用 `--static`，完整八维审查使用宿主导入或已配置服务的 `--semantic`。
- 以报告中的语义状态区分未请求、完成、失败；行为评测单独依据 Benchmark 记录。普通 `audit` 不执行行为回归。
- 当前为八维百分制设计分。四项标准记录达标与不足证据，和缺陷扣分上限取较低值；不代表执行成功率。纯静态六维暂评、职责边界与异常处理待语义审查；完整审查后八维均有分。未运行行为评测不扣设计分。检查脚本只做候选识别，存在不等于通过。
- 已配置的远程语义服务遇到短暂网络错误时，CLI 会有限重试；语义阶段仍失败时保留静态报告并明确返回未完成状态，不伪造完整八维结论。没有远程服务时可使用宿主导入完成语义审查。
- 汇报先说明本轮检查范围，再给主要发现、证据和下一步建议。Token 是启发式估算；案例生成与真实模型评测的用法按需查看项目 README 和评测文档。

## 验证

命令回显 `已写入 <路径>`，文件存在且能按所选格式读取，表示报告已生成。读取报告中的工具版本、语义状态和问题证据，再形成审查结论。

退出码 0 表示命令完成且满足所选门槛，`--fail-on none` 下仍可能有错误级问题；2 表示输入、运行或语义审查失败，即使保留了静态报告也应说明失败阶段。1、3 等命令相关退出码见 `skill-doctor --help`。

用户询问首次安装、没有模型服务、静态与完整审查的取舍、失败后的处理或评分含义时，读取[常见问题](references/faq.md)。
